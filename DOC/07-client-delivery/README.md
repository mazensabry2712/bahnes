# Client Delivery

## Standard engagement lifecycle

1. **Qualify:** Confirm the problem, decision-maker, budget, urgency, and fit.
2. **Discover / survey:** Map the workflow or site, users/equipment, constraints, risks, existing systems, and acceptance conditions.
3. **Propose:** Document deliverables, exclusions, timeline, dependencies, itemized price, and payment milestones.
4. **Contract and kickoff:** Obtain written approval, agreed advance payment, site/data permissions, and named contacts.
5. **Plan:** Break scope into demonstrable milestones and confirm who signs off.
6. **Deliver:** Work safely, use version control for software, configure/install within scope, and record important decisions.
7. **Test and accept:** Run agreed checks and record customer feedback/sign-off.
8. **Release / commission:** Follow the appropriate release or installation checklist; protect data and preserve a rollback/recovery path where applicable.
9. **Handover:** Provide user guidance, access/ownership transfer, as-built/configuration notes, known limitations, and agreed source-code/license information.
10. **Support:** Start only the warranty/support terms agreed in writing.

## Track-specific delivery requirements

### IT / CCTV / networking
- Confirm site access, authorized contact, scope/layout, electrical/network prerequisites, equipment models, compatibility, and cable route before installation.
- Agree what is and is not included: civil work, conduit, extra cable, internet service, electrical work, subscriptions, remote-access setup, and equipment replacement.
- Protect credentials and restrict access to devices/recordings to authorized people.
- Test coverage/connectivity/recording/network behavior against the agreed acceptance criteria.
- Document device inventory, configuration handover, warranty, customer-owned accounts, and maintenance responsibilities.
- Do not imply a particular camera coverage, cybersecurity level, warranty, or emergency response before it is confirmed.

### Software / websites / applications
- Confirm user roles, workflows, acceptance criteria, content/data ownership, integrations, migration, environments, and dependencies.
- Use version control and appropriate automated/manual tests.
- Review authentication/authorization, input validation, logging/privacy, backups, deployment, and rollback as applicable.
- Handover deployment notes, administrator guidance, dependencies, license/IP terms, known limitations, and support scope.
- Do not move customer data or production traffic without agreed authorization and a recovery plan.

## Customer responsibilities

Define who supplies content, credentials, site access, sample data, business rules, feedback, approvals, power/network access, and vendor accounts. Never ask for production secrets through a public issue or repository.

## Acceptance

Acceptance must be observable, not just “looks good.” Define:
- Expected behavior or installation outcome.
- Required role/device/browser/environment.
- Valid and invalid cases, including failure scenarios.
- Relevant data, network, or integration prerequisites.
- Who tests and approves, and by when.

## Defects vs. changes

A defect is a failure to meet agreed scope. A new workflow, device, integration, report, extra cabling route, revised coverage, or expanded migration is a change request that can affect price/date. Record the difference before starting extra work.

## Release, handover, and support

- [ ] Scope/version or equipment list approved.
- [ ] Relevant tests/commissioning checks completed.
- [ ] Backup/recovery or rollback path considered and documented where applicable.
- [ ] Secrets configured outside source control and transferred securely.
- [ ] Licenses, vendor fees, warranty, and support boundaries explained.
- [ ] Customer acceptance/release authorization recorded.
- [ ] Documentation, ownership, and contact route handed over.
- [ ] Support start date and terms documented.

After successful delivery, request feedback and permission to publish a case study. Never expose confidential information or claim unverified outcomes.
