# Project Management

## Lightweight workflow

Use one central task board. A task should have an owner, a clear outcome, priority, acceptance check, and links to relevant context. For a solo founder, avoid introducing tools that duplicate the same information.

## Suggested stages

Backlog → Ready → In progress → Review/Test → Blocked (when applicable) → Done.

Keep work-in-progress limited. Finish and verify important tasks before starting too many new ones.

## Definition of Ready

A task is ready when:
- The problem and desired result are clear.
- Scope and exclusions are understood.
- Dependencies and access are known.
- Acceptance criteria can be checked.
- Risk and estimate are reasonable for the next milestone.

## Definition of Done

A task is done when:
- The agreed behavior works.
- Relevant tests/checks pass.
- Edge cases and errors are considered.
- Code is reviewed by the author against project conventions.
- No secrets or sensitive data were committed.
- Necessary documentation is updated.
- Deployment and customer acceptance requirements are met.

## Change control

For a scope change:
1. Record the request and its business reason.
2. Estimate effort, cost, risk, and schedule impact.
3. Explain options (replace an item, add budget/time, or defer).
4. Obtain written approval.
5. Update the delivery plan and relevant proposal/contract.

## Risk register

Maintain a small table of risk, likelihood, impact, mitigation, owner, and review date. Track at least: unclear scope, delayed approvals, unpaid milestones, external-provider issues, data loss, security exposure, and founder availability.

## Decision log

Record major choices with date, context, alternatives, selected option, reason, and review trigger. This prevents repeated debate and makes future collaborators easier to onboard.

## Weekly review

Review completed work, blocked work, upcoming deadlines, risks, unpaid invoices, customer decisions needed, and next week's highest-value outcome.
