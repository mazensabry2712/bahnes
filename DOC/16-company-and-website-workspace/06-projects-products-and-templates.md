# 06 — Projects, Products & Website Templates

## Three distinct content types

### Projects / Case Studies
Purpose: demonstrate actual work and engineering judgment. Include context/problem, constraints, BAHNES role, approach, deliverables, images approved for publication, and verified result if evidence exists. Use Completed, In Progress, Concept, or Confidential. Never present a demo as a customer engagement.

### Products
Purpose: offer repeatable software. Include the buyer/problem, capabilities and limitations, real screenshots/demo, supported environment, prerequisites, integrations, license/price only when approved, setup, support/update boundaries, and security/data considerations. Version and availability must be accurate.

### Website Templates
Purpose: offer reusable designs or implementations under explicit license. Include business fit, desktop/mobile screenshots, live preview if available, included pages/files/components, dependencies, localization/accessibility/SEO scope if verified, customization scope, price/license, updates/support, delivery format, version, and limitations.

## Implementation status

- **Products admin:** list/search/status filter, create/edit, bilingual fields, preview/demo URL, draft/published/archived state, display order and optional scheduled publication.
- **Website Templates admin:** a separate catalog with its own fields for included pages, customization, preview/demo, license, delivery and support terms.
- **Publication guard:** Products and Templates can be published in a locale only when that locale has a title, slug and summary plus license, delivery and support terms. No price is assumed, and public checkout is not enabled.
- **CI verification:** [run 40099542157](https://github.com/mazensabry2712/bahnes/actions/runs/40099542157) passed 43 tests (165 assertions), TypeScript checking and the Vite production build.
- **Still pending:** public catalog pages, screenshots/media management, real product/template inventory and final commercial terms.

## Publishing rules

- Obtain permission for customer names, logos, screenshots, and confidential details.
- Label concept demos accurately and use only synthetic data where needed.
- Never invent reviews, numbers, results, or endorsements.
- Explain whether BAHNES built, customized, maintains, or merely showcases an item.
- Use distinct public URLs and metadata for each item.

## Catalog experience

Start with simple categories; add search/filters only when catalog size warrants it. Comparison features and account-based downloads are not launch requirements.

## Selling boundaries

Start with Request a Demo, Request a Quote, or Request Customization. Add Buy Now only after payment handling, license acceptance, order confirmation, delivery, refunds/cancellation, tax/accounting, and support have been defined and tested.

## Readiness gate

Confirm demand, feature scope, demo safety, license/pricing, delivery/update/support processes, and a customer reporting route before an item is called ready for sale.
