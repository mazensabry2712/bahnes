## Documentation rules

1. Update the canonical document when a decision changes; avoid conflicting copies.
2. Mark information Proposed, Needs confirmation, Approved, Implemented, or Verified when status matters.
3. Record major decisions with context, alternatives, reason, and review trigger.
4. Never commit passwords, API keys, payment credentials, production secrets, or private customer data.
5. Verify legal, tax, license, security, and pricing matters with current official sources or qualified advisers.
6. Record test results only when checks were actually run.
