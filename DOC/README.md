## How to use this documentation

1. Update the canonical document when a decision changes; do not create conflicting copies.
2. Mark important items as Proposed, Needs confirmation, Approved, Implemented, or Verified.
3. Record major decisions with context, alternatives, reason, and review trigger.
4. Never commit passwords, API keys, payment credentials, production secrets, or private customer data.
5. Verify legal, tax, license, security, and pricing details with current official sources or qualified advisers.
6. Claim a test or release check passed only when it has actually been run and recorded.
