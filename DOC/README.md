## How to use this documentation

1. Keep decisions and current facts here; label estimates and hypotheses clearly.
2. Add a dated decision record when a major business or technical decision changes.
3. Update the relevant subject folder instead of duplicating the same policy in several places.
4. Never store passwords, API keys, private customer data, payment credentials, or production secrets in Git.
5. Treat legal, tax, and price guidance as review items until verified against current official sources or a qualified adviser.
