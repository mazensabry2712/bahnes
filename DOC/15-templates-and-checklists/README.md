# Templates & Checklists

This folder is the index for reusable working templates. Keep templates lightweight and adapt each one to the engagement. Legal agreements must be reviewed for the actual transaction by qualified counsel.

## Recommended templates to create and maintain

### Sales
- **Lead record:** Company, contact source, segment, problem, status, next action/date.
- **Discovery notes:** Current workflow, pain, impact, urgency, buyer, budget, constraints, agreed next step.
- **Proposal checklist:** Problem, deliverables, exclusions, milestones, assumptions, price, taxes, dependencies, acceptance, support.

### Delivery
- **Project kickoff:** Stakeholders, contacts, scope, communication cadence, access, test data, customer responsibilities.
- **Requirements brief:** User roles, workflows, business rules, acceptance criteria, integration and migration needs.
- **Change request:** Requested change, reason, options, price/time impact, approval.
- **Release checklist:** Tests, configuration, data backup, migration, monitoring, rollback, release authorization.
- **Handover checklist:** User guidance, admin ownership, credentials transfer, known issues, source-code/licensing notes, support start date.

### Operations
- **Weekly review:** Pipeline, delivery, blockers, invoices, cash, top priorities.
- **Monthly financial review:** Collected cash, outstanding receivables, direct costs, expenses, reserves, forecast.
- **Risk register:** Risk, likelihood, impact, mitigation, owner, review date.
- **Decision record:** Date, context, alternatives, decision, trade-offs, review trigger.
- **Incident record:** Time discovered, containment, systems/data affected, actions, notifications, follow-up.

## Template quality rules

- Use explicit placeholders, not invented customer data.
- Keep confidential customer documents out of the public repository.
- Do not put real credentials, IDs, personal data, or payment details into examples.
- Date and version templates when a material process changes.
- Clearly label sample/demo content.
- Keep one canonical template per purpose and link to it rather than copying stale variants.
